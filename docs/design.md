# Agent 足迹（暂名）设计

- 日期：2026-11-03
- 状态：已批准
- 范围：首个可用版本

## 1. 意图

用户交替使用多种编码 Agent，常常只记得“昨天做过某个东西”，却想不起用了哪个工具、位于哪个目录、做了什么。Agent 足迹要做成跨 Agent 的本地工作记忆：把各工具已经存在的会话记录汇入同一条时间线，并尽量一键回到原来的 Agent 会话继续工作。

首版的价值不是再造一个聊天客户端，而是缩短“模糊回忆 → 找到工作现场 → 继续工作”的路径。

## 2. 用户已确认的决策

- 主界面是按日期分组的跨工具时间线，不是按工具分开的会话列表。
- 点开记录后，首要动作是回到原 Agent 的原会话和项目目录。
- 不改变现有使用习惯；自动发现各 Agent 已保存的本机会话，不要求从统一启动器启动。
- 产品形态为本地网页控制台，由本地后台进程提供数据。
- 首版采用元数据优先，不做全量对话、命令和差异索引。
- 需要考虑的 Agent 包括 Kimi Code、CodeBuddy、MiniMax Code、ZCode、DeepSeek Harness、Pi、OpenCode、Codex 和 Claude Code。

## 3. 目标、非目标与反目标

### 目标

- 在一条时间线上回答：什么时候、哪个 Agent、哪个目录、原生标题是什么。
- 保留原工具、会话 ID 和源位置，支持能力明确的原会话恢复。
- 对已发现的数据格式提供只读适配器，并以统一模型展示。
- 自动进行增量扫描，同时提供手动刷新。
- 所有数据留在本机；本地索引不保存会话正文。
- 各工具能力不同时诚实降级，不伪造统一的标题、改动统计或恢复能力。

### 非目标

- 统一聊天、统一启动所有 Agent 或替代原工具。
- 首版进行全文搜索、语义搜索、AI 摘要或云端同步。
- 首版统一还原每个文件的差异、终端滚动内容或未保存的编辑器状态。
- 修改、压缩、清理或迁移原 Agent 的会话数据。
- 支持任意未来 Agent 的零配置接入；新工具仍需新增适配器。

### 反目标

- 需要用户手动打卡或记得维护记录。
- 为了生成标题而上传代码或对话。
- 把“成功启动进程”显示成“已确认恢复原会话”。
- 为追求界面一致而隐藏某个工具实际缺失的信息。

## 4. 已验证的本机事实

以下结论来自只读检查，未读取会话正文，只查看了目录、字段名、数据库结构和 CLI 帮助。

| Agent | 可用元数据 | 恢复方式验证情况 |
| --- | --- | --- |
| Kimi Code | `session_index.jsonl` 有会话 ID、会话目录和工作目录；`state.json` 有标题及创建、更新时间 | `kimi --session <id>` 已确认 |
| CodeBuddy | 项目 JSONL 有会话 ID、工作目录和时间戳 | `codebuddy --resume <id>` 已确认；原生标题尚未发现 |
| MiniMax Code | 运行时 SQLite 有会话、项目、标题、目录、时间及原生差异记录 | `mcode --session <id>` 已确认 |
| ZCode | CLI 与任务 SQLite 有标题、目录、时间、会话 ID 和改动统计 | 已确认存在 `zcode://` 协议，具体会话路由未确认 |
| DeepSeek Harness | 会话索引有原生标题；SQLite/项目缓存有目录和时间 | `dst --resume <id>` 已确认 |
| Pi | 项目会话 JSONL 有 ID、目录、时间；命名会话可有原生名称 | `pi --session <id>` 已确认 |
| OpenCode | SQLite 和旧版 JSON 存储有标题、目录、时间及改动统计 | `opencode --session <id>` 已确认 |
| Codex | `state_5.sqlite` 的线程记录有标题、目录、时间和 rollout 路径 | `codex resume <id>` 已确认 |
| Claude Code | 本机只有配置目录，未发现可检查的会话数据 | 本机未找到命令，恢复能力未做本机验证 |

因此，统一架构必须是“适配器 + 通用记录”，不能假设所有工具都有相同字段。

## 5. 考虑过的方案

### 方案 A：元数据优先，本地网页控制台（已选择）

读取原生标题、目录、时间、会话 ID 和已有统计，保存到本地 SQLite。优点是覆盖工具快、隐私边界清晰、首版能解决主要的定位与恢复问题。代价是部分工具可能只有“未命名会话”，找回内容的线索较少。

### 方案 B：渐进深度索引

默认读取元数据，用户选定项目或日期后再读取正文、生成摘要和全文索引。找回能力更强，但首版会多出内容解析、敏感数据边界、索引管理和摘要生成四条复杂路径。

### 方案 C：完整本地档案

一开始索引全部对话、命令和文件差异。信息最完整，但存储和解析维护成本最高，也不符合用户选择的首版范围。

选择 A，并在数据模型中保留可选字段和适配器版本，避免以后增加深度索引时推翻首版。

## 6. 首版产品行为

### 启动与扫描

- 启动本地服务并打开控制台；首次执行全量扫描，之后默认每 30 秒增量扫描，也允许手动刷新。
- 适配器只扫描明确列出的会话位置，不遍历整个用户主目录。
- 用源路径、文件大小、修改时间和适配器版本判断是否需要重新解析；SQLite 使用短时间的只读查询。
- 某适配器不存在、无权限或解析失败，不影响其他适配器。
- 界面显示最近扫描时间和各适配器状态，失败信息不包含会话正文或凭据。

### 时间线

- 按本地日期分组，按最后活动时间倒序；提供今天、昨天、最近 7 天快捷筛选。
- 支持按 Agent、项目目录和标题/目录文本筛选；这不是会话全文搜索。
- 默认一张卡对应一个原会话，保留原生标题、工具、目录、时间和已有改动统计。
- 同一 Agent、同一规范化工作目录且相邻间隔不超过 45 分钟的会话，可以折叠为一个“工作段”；工作段必须能展开看到每个原会话。这个阈值和展示方式是设计者的默认选择。
- 没有原生标题时显示“未命名会话”，以目录和时间辅助识别；首版不读取首条用户消息来补标题。
- 原生标题为空、统计缺失或源记录已删除时，明确显示未知或不可恢复，不猜测。

### 详情与工作现场

详情至少包含：Agent、原生标题、会话 ID、工作目录、首次/最后活动时间、源记录位置、已有改动统计、恢复能力。

主按钮为“回到原会话继续”：

- 对已验证 CLI 适配器，在原工作目录启动一个新的终端窗口，并执行对应的恢复命令。
- 不自动追加新提示词，不 fork 会话，不切换分支，不清理工作区。
- 工作目录不存在时停止并说明，不静默改到其他目录。
- 进程参数使用参数数组传递，不把会话 ID 或目录拼进 shell 字符串。
- 只能确认终端/进程是否成功发起；原工具内的恢复结果由原工具展示。
- 对尚未验证恢复路径的工具，隐藏恢复按钮并标注“目前仅支持查看”；可以提供普通的“打开项目目录”动作。

### 原记录变化与删除

- 原记录更新时更新本地元数据和扫描指纹。
- 原记录删除后保留最后一次本地元数据，标记“源记录已缺失”，禁用恢复；不声称还能打开原会话。
- 用户在首版只能刷新和查看，不提供会修改原会话的操作。

## 7. 通用数据模型

核心对象为 `ActivitySession`，建议字段如下：

- `source`：工具标识，如 `kimi-code`。
- `session_id`：原工具会话 ID；适配器必须保证在来源内稳定。
- `workdir`：原始工作目录；另存规范化形式用于筛选和工作段折叠。
- `title`：原生标题，可为空。
- `title_source`：`native`、`fallback` 或 `missing`，首版不得是 `ai`。
- `created_at`、`updated_at`：带时区或可正确转换的时间戳。
- `additions`、`deletions`、`files_changed`：仅使用原工具已经提供的统计，均可为空。
- `source_locator`：重新解析所需的路径或数据库标识，不用于展示正文。
- `resume_kind`：`cli`、`deep_link` 或 `none`。
- `resume_ref`：恢复所需的 ID 或经验证的深链；不等于可直接执行的字符串。
- `source_missing`、`archived`：原记录状态。
- `adapter_version`、`source_fingerprint`、`last_scanned_at`：增量扫描与排错信息。

“工作段”是查询时的展示分组，不覆盖或删除原会话记录。

## 8. 适配器契约与来源

每个适配器实现四个边界：

1. `discover`：确认数据源是否存在并报告版本/可读性。
2. `scan`：返回通用元数据和下次增量扫描所需指纹。
3. `status`：报告不支持、数据缺失、版本不兼容或暂时失败。
4. `resume_plan`：返回结构化恢复计划；没有能力时返回 `none`，UI 不自行猜命令。

首版数据来源：

| 适配器 | 首选来源 | 备注 |
| --- | --- | --- |
| Kimi Code | `~/.kimi-code/session_index.jsonl` 与对应 `state.json` | 不导入 `lastPrompt` 或 wire 正文 |
| CodeBuddy | `~/.codebuddy/projects/**/*.jsonl` | 只取元数据字段；无原生标题时使用 fallback |
| MiniMax Code | `~/.minimax/v2/sqlite/runtime-state.sqlite` | 只查询会话、项目和已有差异统计相关表 |
| ZCode | `~/.zcode/cli/db/db.sqlite` 与 `~/.zcode/v2/tasks-index.sqlite` | 首版可导入时间线；深链验证前 `resume_kind=none` |
| DeepSeek Harness | `~/.dsh-tui/session-index.json`、`sessions.sqlite` 和 `~/.dsh/storages/` 元数据 | 优先使用已有标题和索引，不解压正文档案 |
| Pi | `~/.pi/agent/sessions/**/*.jsonl` | 只读取会话元数据和原生命名记录，不取消息内容 |
| OpenCode | `~/.local/share/opencode/opencode.db`，必要时兼容 `storage/session/**/*.json` | 同一会话只能导入一次 |
| Codex | `~/.codex/state_5.sqlite`，rollout JSONL 作为元数据回退 | 不导入 `first_user_message`、`preview` 等正文字段 |
| Claude Code | 检测到 `~/.claude/projects/` 后再启用对应解析器 | 标为实验；无数据时不产生空记录或虚假支持状态 |

数据库以 `mode=ro` 打开，不执行 checkpoint、vacuum、迁移或写事务。源格式变化时适配器应报告不兼容，而不是根据字段名猜测正文含义。

## 9. 技术组成（设计者的实现选择）

这些是实现默认值，不是用户指定的技术偏好：

- Python 3 后端，优先标准库，减少对当前空项目引入依赖。
- SQLite 作为本地索引；不复制原数据库。
- 原生 HTML/CSS/JavaScript 的单页控制台。
- 本地 HTTP 服务只绑定 `127.0.0.1`。
- 独立终端启动层，检测可用终端并允许用户配置参数数组模板。
- 建议产品命令和数据目录暂用 `agent-trail` 与 `~/.agent-trail`；命名可在实现前替换，不影响架构。

模块边界：扫描调度、适配器、规范化与去重、本地索引、查询 API、网页 UI、恢复/终端启动、状态与错误展示。

## 10. 隐私与本地服务安全

- 明确禁止读取各工具的 credentials、auth、token、密钥、Cookies 和普通配置文件。
- 本地索引只保存第 7 节列出的元数据，不保存消息、命令、代码、diff 或附件。
- HTTP 服务使用每次启动生成的高熵访问令牌；完整 URL 交给本机浏览器，查询和变更接口都校验令牌。
- 恢复和刷新使用 POST，并检查请求来源，避免其他网页诱导本机服务执行动作。
- 恢复命令来自适配器白名单；路径和会话 ID 只作为独立参数传递。
- 日志默认只记录工具名、状态、记录数量和错误类型，不记录标题、路径或会话正文；调试模式也需主动开启。
- 网页只展示本机数据，不加载第三方统计、字体或脚本。

## 11. 错误与边界情况

- 单行 JSON 损坏：跳过该条并增加错误计数，不丢弃整个源文件。
- 数据库忙或正在写入：短查询失败后退避重试，不写源库。
-  Schema 不兼容：暂停该适配器并显示版本问题，其他工具继续工作。
- 重复会话：以 `source + session_id` 去重；跨存储迁移时优先信息更新、更完整的记录。
- 会话正在运行：允许刷新元数据；恢复前不终止已有进程，冲突由原工具处理。
- 项目目录被移动：显示原目录和缺失状态，不自动搜索同名目录替换。
- 原 CLI 不在 PATH：禁用恢复并提示配置可执行文件路径，时间线仍可查看。
- Claude Code 或 ZCode 恢复未验证：绝不显示可用的“回到原会话”按钮。

## 12. 验收方式

首版完成后需要在实际交付形态中验证：

1. 启动本地控制台，真实扫描本机数据源，时间线出现来自不同 Agent 的记录。
2. 检查本地索引和日志，确认没有消息正文、代码、diff、token 或凭据。
3. 验证日期、Agent、项目和标题/目录筛选，以及工作段展开后仍能定位单个会话。
4. 对每个已声称支持恢复的适配器，使用真实记录验证生成的恢复计划；实际点击后由原工具确认打开了预期会话。未做真实验证的适配器不得标为“可恢复”。
5. 模拟源文件损坏、目录缺失和 CLI 不存在，确认错误局部化且不会误启动其他工作区。
6. 验证外部网页无法在无令牌情况下读取记录或触发恢复。
7. ZCode 只验收时间线导入，除非具体会话深链已通过真实点击验证；Claude Code 只在有真实环境和记录时取消实验标记。

## 13. 留给实现者的决定

- 具体代码目录结构、前端视觉细节和组件拆分。
- 各数据库的精确 SQL、版本探测和兼容字段映射。
- 增量指纹的编码、扫描退避参数和大数据量下的分页方式。
- Linux 终端检测顺序和用户配置界面。
- 是否保留暂名及命令名。

实现者不应自行加入全文索引、AI 摘要、云同步、统一启动器或修改原会话的功能。

## 14. 已知限制

- 元数据优先意味着部分记录只有“未命名会话”。
- 本版主要依据本机现有格式，工具升级后需要维护适配器。
- ZCode 的原会话恢复仍需验证具体深链；Claude Code 需要真实安装与记录才能完成验证。
- “回到工作现场”指原 Agent 会话与目录，不保证恢复当时未保存的文件或完整桌面布局。
